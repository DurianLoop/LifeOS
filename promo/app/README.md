# LifeOS · 随身日记

使用入口：**https://lifeos-diary.netlify.app/app/**

这是 LifeOS 手机网页版的首个版本（v0.1），使用原生 HTML、CSS、JavaScript 和 IndexedDB。无需账号即可记录、编辑、搜索和翻阅文字日记；完成首次缓存后，可离线打开。它与桌面版 v0.5.2 的版本号分别维护。

## 在 iPhone 上使用

1. 用 Safari 打开上面的入口。若在微信等应用内打开，先选择用 Safari 打开。
2. 保持联网，等待首页出现「离线已就绪」。
3. 点击 Safari 的「分享」→「添加到主屏幕」→「添加」。
4. 从主屏幕打开 LifeOS，再确认页面已离线就绪，然后开始记录。

Safari 页面和主屏幕应用的数据可能独立。若安装前已写过日记，先在「我的 → 导出备份」保存文件，再检查主屏幕应用的「旧页」；需要时导入该文件。AI 问答始终需要联网。

## 当前功能

- **今天 / 落笔**：每天一页，可补写其他日期；草稿自动保存在本机，编辑后保留最近 20 个历史版本。
- **旧页**：按日期翻阅、关键词搜索、按月筛选、继续编辑；删除后进入可恢复的回收站。
- **问自己**：手动选择 1–6 页记录，预览并编辑摘录后再发给 AI；回答下方可返回对应日记原文。
- **我的**：安装说明、JSON 备份与导入、请求持久存储、AI 配置和回收站。

此版本支持文字日记，不提供照片、录音、桌面端自动同步或云端账号。日记正文按文字显示，导入的 Markdown 内容会完整保留，不执行其中的 HTML。

## 本机保存与备份

日记、草稿、回收站和模型服务偏好保存在当前浏览器或主屏幕应用的 IndexedDB 中，写入事务完成后才显示保存成功。它不是云端备份，也未额外加密本机数据库。清理网站数据、移除应用或系统回收存储可能造成记录丢失；持久存储申请是否获准由浏览器决定，不能替代备份。

在「我的 → 导出备份」生成 JSON 文件。iPhone 支持文件分享时会打开系统分享面板，请选择存储到「文件」；其他浏览器使用下载。备份是明文，包含正常日记、回收站、草稿和保留的编辑历史，不包含 API Key、模型设置或 AI 回答。请确认文件已保存，并妥善保管。

导入会先验证整份文件，再执行一次写入事务。重复内容跳过，同一日期或 ID 存在不同内容时保留本机记录并报告冲突，不覆盖现有日记。已有草稿也会保留；导入草稿对应的原页发生变化时，将其作为独立草稿保留，保存前需核对日期。

### 与桌面版交换日记

桌面版选择 **JSON 日记导出**，再在手机版「我的 → 导入日记」选择该文件。手机版保留每页的完整正文，包括原有 Markdown 章节；此次导入范围是每日文字日记。包含周记等其他类型时会拒绝整份导入，请在桌面版仅选择日记重新导出。

手机版备份的 `entries` 使用桌面导入器可识别的 `journal_date`、`title`、`content` 等字段，可在桌面版导入正常日记。手机版专用的 `trash`、`draft`、编辑历史不用于桌面恢复。此方式不迁移附件、桌面数据库、原始修订身份或全部元数据，也不是完整的桌面备份恢复。两端均按日期保存每日一页，导入前请核对桌面端的冲突预览。

单次导入最多 10 MB、5,000 条记录；每页标题最多 200 字、正文最多 50,000 字。超过限制时请保留原文件并分批导出。

## 可选 AI 问答

在「我的」选择 DeepSeek、OpenAI 或通义千问（中国站），填写模型名称与自己的 API Key。模型费用由相应服务商向你的账户计费。Key 仅存于当前页面内存，不写入 IndexedDB、浏览器缓存或备份；刷新或重新打开页面后需重新填写，也可手动清除。

提问流程是「选择记录 → 预览摘录 → 确认发送」。每页默认截取前 1,600 字，可在预览中调整；问题最多 2,000 字，全部摘录最多 10,000 字。确认后，Key、问题、所选日记的标识、日期、标题和摘录经本站 `/.netlify/functions/mobile-ask` 转发给选定服务商；不会自动上传整个日记库。

网关只允许固定的三家服务商地址，不使用站点共享 Key，不主动保存或记录请求正文与 Key，响应标记为禁止缓存。Netlify 和所选模型服务仍参与请求处理；这不是端到端加密通道，也不代表服务商不保留请求。Service Worker 仅缓存应用静态文件，不缓存问答请求或响应。

提示词要求 AI 根据摘录作答、区分事实与推测，并引用来源；这不能保证模型判断正确。停止等待会取消浏览器请求，但已送出的请求仍可能被服务商处理。当前页面显示的回答不会写入日记或备份。

## 开发、检查与发布

以下命令均在仓库根目录运行。需使用支持当前测试选项的 Node.js 版本。

```sh
node promo/serve.mjs
# http://127.0.0.1:4173/app/

node --test --experimental-test-isolation=none tests/mobile-*.test.mjs
node promo/build.mjs
```

构建当前会输出 40 个公开文件到 `promo/dist/`，并按应用资源内容生成 Service Worker 缓存版本。新版本会等待旧页面关闭后激活，避免强制刷新正在书写的页面。

正式离线检查应使用构建产物。PowerShell 示例：

```powershell
node promo/build.mjs
$env:LIFEOS_PROMO_PORT = '4174'
$env:LIFEOS_PROMO_DIST = '1'
node promo/serve.mjs
# http://127.0.0.1:4174/app/
```

先联网打开并等待「离线已就绪」，再断网重开、写入、刷新并检查日记。环境变量仅用于本地预览；源文件预览使用固定开发缓存名，不能代替构建产物的升级检查。

手动发布现有站点时，静态资源和 AI 函数必须同时部署：

```sh
node promo/build.mjs
netlify deploy --no-build --prod --dir=promo/dist --functions=netlify/functions --site=07817627-cc67-497b-82e7-fb5cf9516223
```

不要继续使用旧的纯静态上传脚本，否则部署可能缺少 AI 网关。仓库根目录 `netlify.toml` 已声明函数目录。浏览器尺寸模拟和自动测试不等于实机验证；iPhone 的系统分享、主屏幕安装与存储生命周期仍需在实际设备上检查，真实 AI 响应需用有效的自有 Key 验证。
