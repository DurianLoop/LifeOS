# LifeOS：v0.4.1 到 v1.0.0

评估日期：2026-10-06

依据：已发布的 v0.4.1 源码副本、发布校验记录，以及现有档案、AI 和界面验收报告。本轮为代码与报告审阅，没有重新执行全量测试。以下区分已验证能力、静态审阅发现和建议目标。

按最新范围，v1.0 面向普通用户，覆盖 PC、Mac、Android、iOS 与同步，能够长期可靠地记录、阅读、查找和按需获得有来源的 AI 回答。

纸张、书本、诗词和自然声音构成现有产品辨识度。后续设计沿用 v0.4 的视觉语言，让这些体验和稳定的数据流程一起成熟。

## 先做 v0.4.2：保存与升级可靠性

### 草稿及偏好跨重启保留

静态发现：`desktop/main.cjs` 默认使用随机端口，`app/v012.js` 将草稿存入 localStorage；字体、纸格等部分偏好也依赖浏览器本地存储。localStorage 按包含端口的来源隔离，所以重新启动后可能看不到之前的草稿和偏好。

建议将草稿和用户偏好持久化到工作区，通过本地接口读取，浏览器存储仅作即时兜底。为已有浏览器草稿设计迁移与找回流程。临时固定端口无法完整解决占用、历史端口和备份问题。

现有打包测试验证了已保存日记、设置和桌宠重启保留，应新增真正退出并重新启动的草稿与布局测试。草稿写入失败当前会被静默捕获，也应显示明确失败状态。

验收：未正式保存的文字在退出、进程终止、重启和升级后可找回；更换监听端口不影响状态；显示的保存状态与实际持久化结果一致。附件草稿另外验证，不能只验证文字。

### 桌面更新完成操作流程

静态发现：主进程和 preload 已有下载、安装接口；前端目前主要调用检查更新并显示状态，未发现下载和安装接口的前端调用。

建议提供检查、下载、取消、重试、重启安装的完整界面。安装前保存草稿、校验下载和完成安全备份；失败时保留原版本和用户数据。

验收：实际从 v0.4.1 升级到下一版本，保留原文、附件、版本、设置和草稿；覆盖网络中断、磁盘不足及下载损坏。当前发布了更新文件，不等于该完整流程已验收。

### 文件、数据库和备份恢复

保存已使用原子替换与 SQLite 事务。文件替换和数据库提交跨越两个存储系统，需要用故障注入确认中途失败后的自动修复，不应只验证正常保存。

备份已包含日记、版本和附件，当前默认放在同一工作区；补充外部目录、定期备份、保留策略、内容校验和恢复预演。草稿及布局偏好纳入可恢复范围。派生数据库的快照也应按一致性方式生成。

验收：独立空白目录可恢复全部受支持内容，逐项比较；人为中断保存或恢复后能够诊断并恢复到一致状态。

## v0.5：极简引导、设置与侧栏

只完善首次使用引导、统一设置入口和侧栏自定义。引导可跳过，AI 可稍后配置；设置首层只放必要内容。侧栏直接进入编辑，拖动排序，拖进阁楼收起，支持取消和恢复默认。延续现有纸张和书本风格。

验收：普通用户可以独立开始写作、导入已有日记，找到 AI 与数据设置；侧栏自定义在重启后保留，收起的功能仍可访问。

## v0.6：跨端与同步

完成 Windows PC、macOS、Android、iOS 的核心写作和阅读体验，以及跨端同步。本版本不扩展阁楼。先确定共用数据协议与客户端边界，专项验证离线编辑、冲突处理、附件、加密与设备恢复。

验收：四端可运行，同一篇日记能跨设备同步；离线修改和冲突可找回，升级不破坏原文与历史。

## v0.7：AI 交互与检索

只实现生成进度、流式展示、用户画像与检索优化。画像应有日记来源，允许用户查看、修正与删除；检索优化用授权真实档案与不同背景样本对比评估。

验收：生成过程可见；支持流式的连接逐步显示内容；画像有依据；检索改进有召回和引用测试记录。

## v0.8：安全、性能与可重复发布

静态发现：本地服务限制在回环地址，但当前请求入口未看到会话鉴权与 Origin/Host 检查。密钥通常走系统凭据库，失败时可回退到 JSON 文件。已存在的加密针对同步载荷，不等于本地 Markdown、附件和备份都已加密。

建议在 v1.0 前完成：

- 本地请求鉴权、来源与主机校验、输入大小限制、路径约束和附件安全打开；Electron 导航、外链、内容策略与依赖专项审计。
- 验证系统密钥库失败时的保存方案；明确选择临时使用、系统加密保护或拒绝落盘，避免将文件权限描述为加密。
- 设计应用锁定与加密备份；说明锁屏与磁盘加密的保护范围。如承诺本地档案加密，先完整设计原文、附件、派生索引、临时文件、恢复密钥与找回流程。
- 使用 0、100、1000、10000 页的合成档案测试启动、搜索、滚动、保存和重建。后台计算分页或分批进行，限制缓存与长列表资源占用。
- 建立自动化打包、空档案审计、Windows 安装与升级测试、校验文件发布及依赖扫描。签名安排在对外推广前。
- 诊断报告默认仅含版本、状态、耗时和错误代码，查看后由用户选择是否导出；不自动包含日记、密钥或完整系统路径。

性能建议目标：在事先声明的普通 Windows 电脑和 10000 页测试档案上，保存响应 p95 <1 秒，本地搜索 p95 <1 秒，常规首次进入可操作界面 <8 秒。以实际测量调整，不视为当前已达到。

## v0.9：公测与发布候选

邀请约 20–30 位不同背景用户连续使用 2–4 周，覆盖初次写日记、已有大量旧日记、仅离线使用和配置 AI 等场景。反馈重点是数据找回、写作阻力、检索可靠性、每周实际回访与难懂入口；这些人数和周期是规划建议。

建立 Windows 10/11、中文与含空格路径、普通权限、不同 DPI、无 Python/Node 环境、代理/无网和磁盘不足的安装矩阵。真实升级必须覆盖旧版本，而不只是从空白环境启动最新安装包。

形成候选版本冻结、缺陷分级、回退与数据恢复文档。新增功能暂停进入候选版，修复后重跑对应流程及完整回归。

## v1.0 的发布条件

| 条件 | 建议要求 |
| --- | --- |
| 数据 | 草稿、原文、附件、版本、备份和恢复能实际验收；无已知丢失或静默覆盖问题 |
| 核心流程 | 新用户独立完成写、读、找、导入、导出和恢复；核心界面无失效入口 |
| AI | 分层保留集完成来源核实；显示发送范围、失败与取消状态；过去视角不混入未来证据 |
| 桌面 | 安装、升级、失败恢复与用户数据保留通过多机矩阵 |
| 隐私 | 本地接口、密钥、公开分享和日志边界通过专项检查；发布包无私人内容 |
| 性能 | 有公开测试条件和测量结果；万页档案可用，后台计算不阻塞写作 |
| 支持 | 常见问题、找回数据、导入格式、AI 配置和诊断导出有清晰说明 |
| 公测 | 建议至少连续两周没有新的数据损坏或核心流程阻断问题，重大隐私问题全部解决 |
